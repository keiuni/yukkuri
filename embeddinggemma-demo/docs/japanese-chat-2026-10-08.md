# スマホで動く小型モデルの日本語（返信・会話）（2026-10-08）

スマホで動く小型の言語モデルに、日本語のメッセージの返信や短い会話をさせて、どのくらい使えるかを調べた記録です。

- **対象**: スマホのアプリで動く Gemma 4 E2B / E4B、ブラウザでも動くもっと小さいモデル、日本語に特化したモデルの 7 つです。
- **問題**: メッセージの返信 8 問、3 往復の会話 3 本、書き換え 5 問、知識 5 問です（[public/data/ja-chat.json](../public/data/ja-chat.json)）。
- **採点**: Claude の採点役 2 人が、モデル名を伏せ、並び順を変えて別々に採点しました。

環境はこれまでと同じクラウドコンテナ（CPU 4 コア、GPU なし）です。モデルは llama.cpp（`llama-server`）で動かしました。
重みの圧縮は、スマホで使われるものに近い 4〜5 ビットにしています（Gemma 4 は Google の量子化学習済み Q4_0）。

## 結論

**返信の下書きや雑談には、Gemma 4 E4B / E2B なら十分使えます。ただし、事実を答えさせるのには向きません。**
それより小さいモデルは、日本語は書けても「誰が誰に言っているか」を取り違えることが多く、下書きの手直しが前提です。

1. **メッセージの返信は Gemma 4 がいちばん自然です。**
   - Gemma 4 E4B: 返信 8 問のうち 81% がそのまま送れ、残りも少し直せば使えました。自然さは 4.8 / 5 です。
   - Gemma 4 E2B: 返信の 56% がそのまま送れ、残りも少し直せば使えました。
   - くだけた口調（「OK🙆‍♂️ 19時新宿ね！ ちょっと遅れそうかも💦」）も、敬語（「承知いたしました。本日中に送付いたします。」）も書けます。
2. **雑談は、システムプロンプトで「短く」と伝えれば使えます。**
   - 何も指示しないと、チャットの一言にも見出しと箇条書きの長文で返します。会話の回答のうち、そのまま使えたのは E4B 22%、E2B 39% でした。
   - 「チャットらしく短く答えて」と 1 文足すと、E4B 89%、E2B 67% になりました（同じ採点役が並べて採点した比較）。
   - 前に言った名前を覚えていて、話のつながりも保てます。
3. **事実の質問は、Gemma 4 E4B 以外は当てになりません。**
   - 日常の事実 10 問を 5 回ずつ聞くと、正答は次のとおりでした。
     - Gemma 4 E4B: 96%
     - Gemma 4 E2B: 66%
     - 日本語特化の 2 つ（LFM2.5-1.2B-JP、TinySwallow-1.5B）: 74%・84%
     - Gemma 3 1B: 46%
   - E2B は「こどもの日」を 5月3日と答える回がありました。「情けは人のためならず」の意味は、E4B 以外はほぼ誤用で答えました。
   - 同じ質問でも、聞くたびに答えが変わります。TinySwallow は東京〜新大阪の所要時間を 5 回で「約3時間」「35〜40分」「2時間30分」「約2時間」「2時間15分」と答えました。
4. **小さいモデルは、立場や向きを取り違えます。**
   - Gemma 3 1B と TinySwallow-1.5B は、プレゼントのお礼で相手に「誕生日おめでとう」と言いました。
   - 敬語への書き換えでは、Gemma 3 1B と LFM2.5-1.2B-JP が、資料を送る人を逆にしました。
   - TinySwallow-1.5B は、夕飯を聞かれて「カレーはいかがでしょうか？」と聞き返しました。
   - そのため、Gemma 3 1B・TinySwallow-1.5B・LFM2.5-1.2B-JP で返信がそのまま送れたのは 6〜13% だけでした。
5. **日本語特化の小型モデルは、雑談の自然さでは Gemma 4 に近いものの、指示どおりに書くのは苦手です。**
   - LFM2.5-1.2B-JP は、会話の自然さが 4.4 / 5 で Gemma 4（4.0〜4.2）と同じくらいでした。ブラウザで動くモデル（0.74 GB）の中では、いちばんバランスがよい結果です。
   - ただし、返信のそのまま使える割合は 13% でした。「短く」と指示しても、よくなりませんでした。
6. **Qwen3.5-2B と Gemma 3 270M は、日本語のやり取りには使えません。**
   - Qwen3.5-2B: 27 回答のうち 5 つに中国語の簡体字（东・为・语 など）が混ざりました。意味の通らない文（「マウスカーソルがすてきすぎやないかな」）も多く出ます。
   - Gemma 3 270M: 質問をそのままくり返すなど、指示に従えません。
7. **速さはスマホで問題になりません。** 公表値では、Gemma 4 E2B は最新のハイエンド機の GPU で毎秒 50 トークン前後出ます。100 文字の返信なら 1〜2 秒です。E4B は 22 トークン/秒です。

**どう使うか**: スマホのアプリで動かせるなら、Gemma 4 E4B（メモリに余裕のある機種）か E2B を使い、システムプロンプトで「短く、チャットらしく」と指示します。
返信は「下書き」として使い、送る前に読んでください。日付・数字・ことわざのような事実は信用せず、必要なら検索と組み合わせます。
ブラウザだけで動かしたいなら LFM2.5-1.2B-JP がいちばんよい結果ですが、文面の質は Gemma 4 E2B より一段下です。

「返信」から「知識」までの列は、その種類の回答のうち「そのまま使える」と判定された割合です。

- **自然さ・合い方**: 1〜5 点です。採点役 2 人の平均で、2 人の差は平均 0.1 点でした。
- **そのまま使える**: 回答のうち「そのまま送れる・使える」と判定された割合です。「少し直せば使える（以上）」はそれに「少し直せば使える」を足した割合です。2 人の判定は 93% で一致しました。
- **事実**: 次の 7 問のうち、答えに必要な語（「富士山」と「3,776」など）が入っていた数です。
  - 知識の 5 問
  - 会話の中で名前を覚えているか
  - 紅葉の時期
- **機械的な問題**: 次のどれかがあった回答の数です（[public/lib/ja-checks.js](../public/lib/ja-checks.js)）。
  - 他の言語の文字の混入
  - 同じ言い回しの繰り返し
  - 字数や箇条書きの数の指示違反
  - 答えに必要な語がない（「事実」の列と重なります）
- 「繰り返し」は、Gemma 4 と Gemma 3 1B では長い箇条書きの見出し（「使用シーン:」「午前:」など）が 3 回出たもので、文が壊れて止まらなくなったわけではありません。Gemma 3 270M では、同じ言い回しを本当にくり返していました。

### 「短く答えて」とシステムプロンプトで伝えた場合

Gemma 4 E4B / E2B と LFM2.5-1.2B-JP には、チャットアプリを想定して次のシステムプロンプトを付けて、同じ 27 問を解かせました。

> あなたはスマートフォンのチャットアプリのアシスタントです。友だちや同僚とのやり取りのように、自然な日本語で短く答えてください。見出しや箇条書きは、頼まれたときだけ使ってください。

| モデル | そのまま使える（指示なし → 指示あり） | 会話 | 返信 | 少し直せば使える（以上） | 回答の平均の長さ |
| --- | --- | --- | --- | --- | --- |
| Gemma 4 E4B | 37% → **81%** | 0% → **89%** | 50% → 63% | 85% → 100% | 264 → 58 文字 |
| Gemma 4 E2B | 30% → **52%** | 22% → **67%** | 38% → 50% | 70% → 85% | 293 → 77 文字 |
| LFM2.5-1.2B-JP | 30% → 22% | 22% → 22% | 13% → 0% | 63% → 59% | 165 → 62 文字 |

この表は 3 回目の採点です。指示なしと指示ありの回答を、同じ採点役がまとめて並べて採点しました。
長い回答が並んで見劣りするぶん、指示なしの値は上の表（1・2 回目）より低めに出ています。比べるのは表の中の矢印の前後です。
Gemma 4 は指示ひとつで会話らしくなりました。LFM2.5-1.2B-JP は短くはなりましたが、質は上がりませんでした。

## スマホで試すには

- **Gemma 4 E2B / E4B**: Google の「AI Edge Gallery」アプリ（[Android](https://play.google.com/store/apps/details?id=com.google.ai.edge.gallery)、[iOS](https://apps.apple.com/us/app/google-ai-edge-gallery/id6749645337)）で、端末の中だけで動かせます。
  ブラウザでは [LiteRT-LM Web 版のデモ](https://huggingface.co/spaces/tylermullen/Gemma4)がありますが、f16 対応の WebGPU と 1 バッファ約 500 MB 以上の GPU が必要です。
- **LFM2.5-1.2B-JP**: このデモの「スマホ実行チェック」（`phone.html`）に追加しました。WebGPU のある端末なら、ブラウザの中で動かせます。
  ページでは、聞く内容と答えの長さを自分で入れられるようにしました。Gemma 3 1B なども同じように試せます。
- スマホの実機での速さは、この環境では測れていません（GPU がないため）。

## 再現方法

```bash
cd embeddinggemma-demo
npm run download-chat-models                        # 7 モデルの GGUF（約 13 GB）
export LLAMA_SERVER=/path/to/llama.cpp/build/bin/llama-server
npm run ja-chat                                     # 回答と機械的なチェック → test-output/ja-chat/<model>.json
npm run ja-chat -- --short gemma4-e2b gemma4-e4b lfm25-jp   # 短く答えるよう指示した版
node scripts/ja-facts.mjs                           # 10 問の事実を 5 回ずつ
node scripts/ja-chat-judge.mjs pack 1               # 採点用の資料（モデル名を伏せて並べ替え）
node scripts/ja-chat-judge.mjs score                # 採点を集計して表を出す
```

採点役には、資料のファイルだけを読み、採点結果を JSON で書くように指示しました（ほかのファイルを開くとモデル名がわかるため）。

## 注意点

- **回答の数**: 各問題の回答は 1 モデル 1 回だけです（事実の問題は別に 5 回ずつ聞きました）。乱数の種を変えると答えが変わります。
  実際に、短く答えるよう指示した回では、Gemma 4 E2B はこどもの日を 5月5日と正しく答えました。
- **採点**: 採点したのは Claude です。人による採点ではありません。ただし、モデル名を伏せ、並び順を変えて 2 回採点させ、判定は 93% 一致しました。
- **速さ**: この環境の速さは CPU（4 コア）の値です。スマホの速さは公表値で、実機では確かめていません。
- **問題の範囲**: 問題は私が作った 27 問で、日常のメッセージと雑談が中心です。長い文章の要約、専門的な内容、敬語の細かい使い分けは調べていません。
