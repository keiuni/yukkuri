# EmbeddingGemma（初代）でメモ・予定・ToDo を仕分ける（2026-10-14）

メモアプリに打ち込んだ短い日本語の文を、**予定**（カレンダーに入れる）・**ToDo**・**メモ**に振り分けて、予定なら日付と時刻まで読み取れるかを調べました。
使ったのは EmbeddingGemma 初代（300M）です（q8 と fp32。[onnx-community/embeddinggemma-300m-ONNX](https://huggingface.co/onnx-community/embeddinggemma-300m-ONNX)）。環境はこれまでと同じクラウドコンテナ（CPU 4 コア）です。

## 結論

**仕分けは、例文を 1 ラベルに 5 つ渡せば約 92% 当たります。日付と時刻は、モデルではなくルール（コード）で読み取るのがよいです。**

1. **仕分け**: 72 文のうち 67 文を正しく仕分けました（93.1%）。ラベルごとに見ると、予定は 24/24、ToDo は 23/24、メモは 20/24 でした。
   - 例文なしで、ラベルの説明文だけでも 86% です。
   - 例文 5 つの平均を使うと 92%、説明文も足すと 93% です。
   - q8（331 MB）と fp32（1.2 GB）は、分類用プロンプトでほぼ同じ正答率でした（平均 + 説明文はどちらも 93.1%）。q8 で十分です。
2. **苦手なのは「日付が入ったメモ」**: 間違えた 5 文のうち 4 文は、メモを予定と取り違えたものでした（「母の誕生日は3月5日（毎年忘れる）」「来年の目標は毎日30分歩くこと」「会議の結論：来期の予算は据え置きで決定」「温泉旅行のプラン案：1日目は箱根、2日目は熱海」）。残りの 1 文は、期限つきの ToDo「来週までに企画書を仕上げる」を予定と取り違えたものです。
   日付や期限が入った文だけ（難問 10 文）だと、正答率は 60% に下がります。
3. **迷ったら聞く作りにすると、間違いを減らせる**: 1 位と 2 位のスコアの差（余白）が 0.05 未満のときだけ、利用者に「予定？ ToDo？ メモ？」と聞く作りです。
   この 72 文では、85% を自動で振り分けて、そのすべてが正解でした。余白 0.03 なら 93% を自動で振り分け、正答率は 96% です。
4. **日付と時刻の読み取りはルールでできる**: 「明日の15時」「来週の火曜日」「再来週の月曜から3日間」「12月1日 13:30」などを日付と時刻に直すルール（[public/lib/note-intent.js](../public/lib/note-intent.js)）を書きました。
   ルールを書いたときに見ていた予定 24 文は、全部正しく読めました。ただし、これはルールを書いた私が作った文なので、独立した確認ではありません。
   あとから別の言い回し 18 文を書いて、ルールをいじらずに試すと 15 文でした。外れたのは「11/20 18:00」「来月の第2土曜日」「正午」で、この 3 つはルールを足しました。
5. **ルールが黙って間違える場合がある**: ルールを足す前の「来月の第2土曜日」は、「来月の」を無視して、今週の土曜（10/17）を返しました（正しくは 11/14）。見たことのない言い回しでは、日付を利用者に確認させる画面が要ります。

## 試したもの

データは [public/data/note-intents.json](../public/data/note-intents.json) です（私が書いた手作りのデータ）。

- **例文（seeds）**: 予定・ToDo・メモを 5 つずつ。利用者が「こういうのが予定です」と見せた例を想定しています。
- **評価用の文（test）**: 予定 24・ToDo 24・メモ 24 の計 72 文。例文とは別です。
  - 日時のない予定（「今度の日曜、午前中に子どもの運動会」）
  - 期限つきの ToDo（「金曜までに請求書を送る」）
  - 日付が入ったメモ（「母の誕生日は3月5日」）など、紛らわしい文を 10 文入れました（表の「難問」）。
- **仕分けの方法**（[scripts/note-intents.mjs](../scripts/note-intents.mjs)）: 文をベクトルにして、各ラベルに近いほうを選びます。
  - 説明文だけ（zero-shot）
  - 例文 5 つの平均ベクトル
  - 例文 5 つの平均 + 説明文
  - 近い例文 3 つの多数決（k-nearest）
- **プロンプト**: モデルカードの分類用（`task: classification | query: `）、検索用（文に query、例文に document）、なしの 3 通り。

## 結果（初代 q8、72 文）

| 方法 | 分類用プロンプト | 検索用プロンプト | なし |
| --- | ---: | ---: | ---: |
| 説明文だけ（例文なし） | 86.1% | 73.6% | 83.3% |
| 例文 5 つの平均 | 91.7% | 75.0% | 91.7% |
| 例文 5 つの平均 + 説明文 | **93.1%** | 75.0% | 91.7% |
| 近い例文 3 つの多数決 | 84.7% | 76.4% | 84.7% |

- **プロンプトは大事**: 検索用のプロンプトだと 75% 前後に落ちます。仕分けには、モデルカードの分類用（`task: classification | query: `）を使います。
- **平均が多数決より良い**: 例文が少ないとき、近い 3 つの多数決は、たまたま似た 1 文に引っ張られます。
- fp32 の分類用プロンプトは、説明文だけ 86.1%、平均 91.7%、平均 + 説明文 93.1%、多数決 83.3% で、q8 とほぼ同じでした（プロンプトなしは q8 より 1〜4 ポイント低い）。
- 時間は、バッチで 1 文あたり q8 が約 0.5 秒、fp32 が約 0.3 秒でした（この環境の CPU、4 スレッド。ブラウザの WASM では、前の測定で q8 が約 0.24 秒）。

「分類用 / 例文 5 つの平均 + 説明文」（上の太字）の混同行列です。

| 正解 ＼ 予測 | 予定 | ToDo | メモ |
| --- | ---: | ---: | ---: |
| 予定 | 24 | 0 | 0 |
| ToDo | 1 | 23 | 0 |
| メモ | 4 | 0 | 20 |

間違いはすべて、「予定」へ取り違えたものでした。予定の見落としは 0 です。カレンダーの予定を取りこぼしたくない用途には、都合のよい偏りです。

### 迷ったら聞く

| 余白のしきい値 | 自動で振り分ける割合 | その正答率 | 残った間違い |
| ---: | ---: | ---: | ---: |
| 0（すべて自動） | 100% | 93% | 5 文 |
| 0.03 | 93% | 96% | 3 文 |
| 0.05 | 85% | 100% | 0 文 |

しきい値は、この 72 文を見て選んだ値なので、実際にはもう少し甘く出ます。

## 日付と時刻

仕分けのあと、予定の文だけルールにかけます。基準日は 2026-10-14（水）です。

| 文 | 読み取った結果 |
| --- | --- |
| 明日の15時から渋谷で田中さんと打ち合わせ | 2026-10-15 15:00 |
| 来週の火曜日、10時に歯医者の予約 | 2026-10-20 10:00 |
| 金曜の夜は会社の飲み会、18時半に新宿集合 | 2026-10-16 18:30 |
| 再来週の月曜から3日間、大阪に出張 | 2026-10-26〜28（終日） |
| 今夜7時に彼女と映画を観に行く | 2026-10-14 19:00 |
| 今度の日曜、午前中に子どもの運動会 | 2026-10-18（時刻なし） |

- 週は月曜〜日曜で数えます。「来週の火曜」は来週の火曜で、曜日だけの「金曜」や「今度の日曜」は、今日より後で最初に来るその曜日です。
- 時刻は、「夜8時」「午後2時」「夕方6時」は 24 時間制に直し、「朝9時」「昼12時」「正午」はそのまま読みます。「午前中」「お昼に」「夜に」は、日付だけ読んで、時刻は空にします。
- ToDo の期限（「金曜までに」「今日中に」）も、同じルールで日付にできます。評価用の 3 文は読めました。

### ルールの限界

- **別の言い回しでは外れる**: 独立に書いた 18 文のうち、最初は 15 文でした。外れた 3 文はルールを足して直しましたが、この 3 文の分は独立した確認ではなくなりました。
- **黙って間違える**: 知らない言い回しは「読めない」ではなく、別の日付を返すことがあります。画面で日付を見せて、利用者が直せるようにしてください。
- **1 文に日時が複数あるとき**（「来週の火曜と木曜の夜に英会話」）は、最初の 1 つしか読みません。
- **タイトルや場所は読めません**: EmbeddingGemma は、文のなかから部分を取り出すことができません。日付と時刻の部分を除いた残りを、そのままタイトルにするのが簡単です。きちんと取り出したいなら、Gemma 4 E2B に JSON で答えさせる手がありますが、動かすコストがかかります（[前の記録](gemma4-phone-2026-10-09.md)）。

## アプリにするなら

1. 文をベクトルにする（EmbeddingGemma 初代 q8、ブラウザやアプリの中で、1 文 0.2〜0.5 秒）。
2. 利用者が最初に見せた例文（各 5 つほど）の平均ベクトルとの近さで仕分ける。余白が 0.05 未満なら、「予定／ToDo／メモ」の選択肢を出して聞く。
3. 予定なら、ルールで日付と時刻を読み、**カレンダーに入れる前に、編集できる確認の画面を出す**。
4. 利用者が選んだ結果は、例文に足していく。使うほど、その人の書き方に合っていきます。

## 試していないこと

- 評価用の文は 72 文で、1 文が 1.4 ポイントです。例文の数や選び方で、数ポイントは動きます。
- 12 通りの設定のなかで一番良いものを選んでいるので、93.1% は少し甘い値です。分類用プロンプトの平均 + 説明文は、モデルカードの指定に従った標準的な設定です。
- 文は私が書いた、きれいな文です。誤字、音声入力の崩れ、英語まじり、長い文、1 つの文に複数の項目が入っているものは、試していません。
- 予定／ToDo／メモの 3 種類だけです。「どれでもない」（雑談や質問）は入れていません。
- EmbeddingGemma 2 は試していません（初代で、とのご希望でした）。

## 再現方法

```bash
cd embeddinggemma-demo
npm run download-model -- --model v1 q8 fp32
npm run note-intents -- --model v1 --dtype q8,fp32     # → test-output/note-intents-v1-<dtype>.json
npm test                                               # 日付と時刻のルールの単体テストを含む
```
